# ELINT box — changes 2026-11-17

Classic fixes made on the box on 11-17 (already in this code; the 11-18 changes in
`CHANGES_2026-11-18.md` build on top). Holdout tools are now in `tools/classic/`.

## Engine code (`~/coderepo/ai_elint`)

| # | File | Change | Setting (default) |
|---|---|---|---|
| 1 | `pipeline/src/classic_v2.rs` | Clock test needs at least 20 pulses actually compared, else "no evidence" (score 0). Before, a radar on air only 0.24 s scored 1.0 from 2 pulses and was merged into another radar. | `CLASSIC_COH_MIN_PAIRS` (20) |
| 2 | `pipeline/src/classic_v2.rs` | Split repair ("join overlaps") no longer joins two look-alike groups whose clocks clearly differ (both directions < `coh_min` 0.04 with >= 20 pulses compared). Two radars of the same type a few MHz apart stay apart. | `CLASSIC_REPAIR_CLOCK_VETO` (1 = on) |
| 3 | `config/classic_library.json` (new), `classic_v2.rs` | Naming rules moved from code to a JSON table (same 8 rules, same order, first match wins). Built into the binary; a different table can be given without a rebuild. | `CLASSIC_LIBRARY=/path.json` |
| 4 | `pipeline/src/onnx_flow.rs`, `classic_v2.rs` | Option: after an ONNX run, join `unknown_ai` emitters whose pulse trains keep the same clock (classic's clock test). Off by default (see results). | `ONNX_CLOCK_MERGE` (0 = off) |
| 5 | `classic_v2.rs` (tests) | 3 unit tests: clock test needs enough pulses, same vs different radar, naming table order. | — |
| 6 | `pipeline/src/tests/refresh_test.rs` | Outdated test updated: a CSV without `id` is allowed on purpose (rows numbered 1, 2, …); a CSV without `power_dbm` still fails. | — |

### Fresh test: 40 new mixed files (never tuned on)

`holdout/` = 40 files, each two test files merged on one time axis (no radar
type twice), 4–14 radars on air at once. Truth = CSV `emitter_id`.
Made with `tools/make_holdout.py` (seed 1117), scored with `tools/run_holdout.py`
(results in `holdout_results.jsonl`).

| Setup | Exact radar count | Known radars named | Extra radars (sum) | Median time |
|---|---|---|---|---|
| Rust classic, before fixes | 38 / 40 | 38 / 40 | −2 | 189 ms |
| Rust classic, now | 38 / 40 | 38 / 40 | −2 | 198 ms |
| Rust ONNX | 0 / 40 | 40 / 40 | +435 | 13.2 s |
| Rust ONNX + `ONNX_CLOCK_MERGE=1` | 0 / 40 | 40 / 40 | +339 | 13.4 s |

* Classic's 2 misses: PSR1 merged into another radar —
  `nav1_nav2_best-6_plus3__psr1_psr5m1_best-3_plus5` (PSR1 and NAV2 pulse
  trains line up by chance, clock scores 0.126 / 0.131, just over the 0.13
  limit) and `cta1_nav2_best-3_plus3__psr1_psr4_best-6_plus5` (PSR1 joined to
  PSR4, same 2750 MHz carrier). Left as known limits on purpose: tuning on
  these files would make them useless as a fair test.
* The ONNX clock merge removes 22 % of the extra radars but no file reaches
  the exact count, so it stays off by default.

## Box

* Kernel packages held (`apt-mark hold`, 6.8.0-138 + hwe metas) so a kernel
  update cannot break the ROCm GPU driver again. Undo: `sudo apt-mark unhold <pkg>`.
* Demo services: `elint-model` and `elint-ui` systemd services start at boot;
  `~/coderepo/start_demo.sh` restarts everything.
* Backup: whole `~/coderepo` copied to nuc2 `/mnt/t9/elint_box_coderepo/`
  (direct rsync; this box's SSH key added on nuc2 for that).

## Not done (and why)

* NPU (AMD XDNA, `c6:00.1 [17f0]`): needs the `amdxdna` driver (newer kernel or
  DKMS) plus AMD's NPU runtime — risky on a box whose GPU driver is pinned to
  kernel 138; a separate test project.
* Mixed-precision model (FP16 with sensitive layers in FP32): needs a model
  conversion and a full accuracy check against Python; not started.
* Live / streaming mode: an engine design change (process every N seconds,
  keep radars across chunks); planned work, not a patch.

## Undo

Copy the files from `originals/` back over `~/coderepo/ai_elint/` and rebuild,
or set `CLASSIC_COH_MIN_PAIRS=0 CLASSIC_REPAIR_CLOCK_VETO=0` to get the old
classic behaviour with the new binary.
